# 写作评测闭环验收（2026-11-05）

## 已贯通

写作用例 → 冻结业务模块与适配器源码哈希 → 持久化队列 → 实际调用 writing-evidence.audit / repair → 结构评分 → 人工复核 → 质量门禁 → 报告导出 → 逐样本对比 → 失败回归集。

当前运行入口：http://127.0.0.1:8765，默认页面为“写作验收”。服务随本机进程存在，重启机器后需运行 start.ps1。

## 操作

1. 点“准备写作评测”：导入8项合成模块用例，注册真实模块和显式回归注入两个目标，冻结源码版本。
2. 点“运行真实模块基线”：8条结构检查通过，但均保留 NEEDS_REVIEW。展开查看输入输出、证据、源码哈希。
3. 在每条样本中依据实际材料填写复核依据并裁决；只有所有预期样本通过，门禁才 PASS。不要把本次合成样本测试记录当成真实论文审签。
4. 点“注入回归并验证”：真实模块运行后，显式清空问题清单或替换修改结果。应检出7条失败，门禁 FAIL；该人为注入不是业务代码真的发生退化。
5. 点“与最近基线逐样本比较”，关注新增失败及样本状态。待复核不计为通过；即使通过率差为零，也能看到新增失败。
6. 点“失败样本转回归集”，在通用实验工作台选取新数据集和真实未注入目标重新运行。应消除结构失败，内容仍需人工复核。
7. 点“导出证据报告”，保留冻结依赖、执行结果与复核记录。

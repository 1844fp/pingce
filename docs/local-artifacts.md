# Local artifact store contract
`apps.api.artifacts.put(project, content: bytes, mime: str) -> dict`; `get(project, artifact_id) -> (meta, bytes)`. ArtifactStore(root) exposes the same methods for isolated tests; default root is repository data/artifacts. Maximum 10 MiB (10*1024*1024); empty bytes accepted. Metadata: id,project,mime,size,sha256. IDs are cryptographically random 64 lowercase hex characters, never filesystem paths. project is a nonempty string up to 200 characters, stored in a SHA256-named namespace. Unknown IDs/cross-project access raise FileNotFoundError; invalid arguments ValueError; corruption raises ArtifactIntegrityError. MIME is allowlisted inert JSON/plain text/Markdown/HTML/PDF/octet-stream; never execute stored content. API must enforce authorization before passing project, and serve downloads as attachments with nosniff (especially HTML). Project isolation is application-level, not OS authentication.

Each artifact is one atomic JSON envelope containing metadata and base64 bytes, avoiding a two-file commit. Temp file created exclusively in destination directory, flushed/fsynced and atomically renamed. Metadata and content integrity validated on every read. Content SHA256 detects accidental content changes; envelope HMAC using store-local key detects metadata/content edits without the key. Protect the root/key with filesystem permissions. A local user able to alter the key and all files defeats this boundary. No delete/update API. Back up root and key together. Single local filesystem; no shared network filesystem guarantee. Symlink/reparse namespace or object paths are rejected; adversarial concurrent filesystem replacement by a privileged process is outside local-MVP guarantees.

Implementation handoff (2026-11-06): 6 isolated pytest cases cover JSON roundtrip/cross-project not-found, metadata tampering, byte tampering, invalid paths/MIME/oversize, exactly-10-MiB payload, empty content and injected atomic rename failure with pending-file cleanup. Test command: pytest tests/test_artifact_store.py -q --basetemp work/artifact-tests-temp. Formal artifact root/evaluation.db untouched by tests. No main.py or migration changes. Parent must add authenticated project-scoped upload/download endpoints, map FileNotFoundError/ValueError/ArtifactIntegrityError distinctly, return inert attachments and avoid accepting filesystem paths. Init key is exclusive-created and fsynced; simultaneous first-use readers may fail closed if key creation is in progress. No automatic retry. Atomic rename assures visibility, not universal power-loss durability (directory fsync not portable here); backup and filesystem permissions remain required. No model/network/services used.

Recovery configuration: set EVAL_ARTIFACT_ROOT to an absolute restored artifact directory before importing/starting the API. Default (unset or empty) stays repository data/artifacts. Pair this with EVAL_DB pointing to the matching restored database; retain .integrity-key. Override is operator configuration, never an upload/request parameter. Store root is selected once at module import; restart the restored service after changing it. Added isolated environment-root test; final suite 7 tests passed.
